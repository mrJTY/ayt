# ayt — All Y'need is Text

```text
    _    __   __ _____
   / \   \ \ / /|_   _|
  / _ \   \ V /   | |
 / ___ \   | |    | |
/_/   \_\  |_|    |_|
    All Y'need is Text
```

A tiny, token-cheap planning loop for agent harnesses: Claude Code, Codex, Antigravity (`agy`), Cursor, pi (see [Install](#install)). Just requirements as text to plan and mark things off as you build things.

## Quick start

```sh
git clone https://github.com/mrJTY/ayt
cd ayt && ./install.sh            # Claude Code; see Install for other harnesses
```

Then, in your own project: `/ayt-init`, then `/ayt-new-idea <idea>`.

## Commands

```
/ayt-init [subdir]      → .ayt/PROJECT.md, requirements/<EPIC>.md, STATE.md
/ayt-new-idea <idea>    → checks existing tickets, asks what we're really solving, then grills the
                          open decisions until none are left, shows a draft ticket for approval, then writes it
/ayt-bug <what's wrong> → dedupes, reproduces, links to the broken ticket, writes BUG-UI-3 (no fix)
/ayt-implement [ID ...] → test-first, sequential, resumable; builds tickets and fixes bugs, never commits
/ayt-review [ID ...]    → like /ayt-pr-review but local, no PR needed: checks the branch's tickets
                          against code + tests and the diff for security / constraints; findings
                          tiered C1 / M1; records pass/fail in the tickets (never edits code)
/ayt-dyb [N] [ID ...]   → do your best: implements, then loops /ayt-review + fixes criticals (N passes,
                          default 2, stops early when clean); after one yes it commits, runs /ayt-pr and
                          posts a fixed / still-open summary on the PR
   (you review + commit)
/ayt-pr [base]          → stops if the tree is dirty; pushes and opens a PR mapping tickets → evidence
/ayt-pr-review [PR]     → reviews the PR against its tickets + security / constraints; after you approve
                          the draft, posts inline comments tiered critical / minor (C1, M1); replies to
                          and resolves earlier findings that are fixed, citing the fixing commit
/ayt-docs [focus]       → writes docs/*.md (overview, architecture, flows with Mermaid sequence +
                          activity diagrams, status) describing the project as it is
```

## Files

```
.ayt/
  PROJECT.md        # what, stack, commands, epics (and their ticket prefixes), constraints
  requirements/
    UI.md           # one epic: a todo list, `- [ ] **UI-12**: title`, detail indented below
  BUGS.md           # one `## BUG-UI-3: title` section per bug (created on first /ayt-bug)
  STATE.md          # current focus, next step, step-by-step progress
```

All planning lives in `.ayt/`. Nothing else in the repo is touched except by `/ayt-implement` and `/ayt-dyb` (code; `/ayt-dyb` also commits, after one yes) and `/ayt-docs` (`docs/` files it generated, marked with a `generated by /ayt-docs` comment; your own docs files are never overwritten).

You may choose to commit `.ayt` directory or not, it's up to you. This project has it's own `.ayt` directory as a dogfood example.

**Bugs** are measured against the requirements: a bug breaks a ticket's acceptance, or is plainly broken (crash, data loss). "Works as specified but I want it different" is routed to `/ayt-new-idea`. Bug status: `open → fixed | wontfix`. Fixing one requires a regression test and a one-line root cause.

**Tickets** are todo lines in an epic file, named like Jira issues: `<PREFIX>-<N>` (`UI-12`, `DB-3`, `PAY-1`). Epics and the prefixes each owns live in `PROJECT.md`. Acceptance bullets, decisions and verification go in bullets indented under the ticket:

```md
- [x] **UI-11**: Settings page saves on blur
- [ ] **UI-12**: Dark mode
  - problem: the app is unreadable at night
  - [ ] toggle in settings, remembered across restarts
  - decision: follows the OS setting until toggled
- [ ] **UI-13** (draft): Theme editor
```

Prefixes keep parallel branches from clashing; `/ayt-pr` catches any that still collide.

**Status**: `(draft)` → `[ ]` ready → `[x]` done. What's been merged is in git; ayt doesn't track it.

**STATE.md** is overwritten, not appended. Implement ticks progress after each step, so a new session can resume mid-ticket.

In a monorepo, `/ayt-init apps/web` creates `apps/web/.ayt/`. Other skills use the nearest `.ayt/` above cwd.

## Token efficiency

- Skills list tickets with one grep (`^- \[` in `requirements/*.md`) and read only the relevant tickets.
- No subagents (except `/ayt-dyb`'s optional fresh-context review pass), no workflow files loaded at runtime. Each skill is a single SKILL.md.

## Install

```sh
./install.sh                      # Claude Code: symlinks skills into ~/.claude/skills
./install.sh codex pi             # one or more harnesses
./install.sh all                  # every supported harness
./install.sh --list               # show targets and where each installs
./install.sh --project cursor     # into <git root>/.agents/skills instead of ~
./uninstall.sh [same arguments]   # remove the links again
```

`uninstall.sh` takes the same targets as `install.sh` and removes only the `ayt-*` links that point into this clone; your own files, directories and other links are left alone, and the skills directories themselves stay.

The same `skills/` are symlinked everywhere; there is no per-harness copy. The links point into this clone, so keep it where it is: `git pull` updates every harness at once, and if you move the clone, re-run `./install.sh` to relink. Re-running also removes links left behind by renamed skills. An existing `ayt-*` file or directory that isn't a symlink is never overwritten: it's skipped with a warning and the script exits 1.

| Target | User dir | `--project` dir | Invoke |
|---|---|---|---|
| `claude` | `${CLAUDE_CONFIG_DIR:-~/.claude}/skills` | `.claude/skills` | `/ayt-new-idea <idea>` |
| `codex` | `~/.agents/skills` | `.agents/skills` | `$ayt-new-idea <idea>` |
| `agy` | `~/.gemini/antigravity-cli/skills` | `.agents/skills` | `/ayt-new-idea <idea>` |
| `cursor` | `~/.agents/skills` | `.agents/skills` | `/ayt-new-idea <idea>` in Agent chat |
| `pi` | `~/.agents/skills` | `.agents/skills` | `/skill:ayt-new-idea <idea>` |

Codex, Cursor and pi share `~/.agents/skills`, so they share one install; every non-Claude target uses `.agents/skills` with `--project`. Commands below are written in Claude Code form (`/ayt-*`); translate per the table. To add a harness, add a line to `target_dirs` in `install.sh`.
